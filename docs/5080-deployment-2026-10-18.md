## 独立部署结构

- 独立 Python 3.12.14 虚拟环境 `.venv`、模型缓存 `cache/huggingface`、输入 `smoke/`、
  两套运行状态 `runs/cpu-gpu-smoke-v1/{cpu,cuda}` 与工作台数据库 `service/anota.db`。
- CPU / CUDA 审核批次各 20 条，来自同一批 20 条录音。
- 用户级 systemd 服务配置 `anota-5080.service`。
- `requirements-lock-5080.txt` 保存实际安装版本；`source-manifest.json` 验证了
  502 个源文件，验收记录为零哈希差异。原 `.git`、虚拟环境、运行数据库和历史音频缓存不被作为代码复制。
- 项目专用 CUDA 12 cuBLAS / cuDNN 安装在 `.venv` 内；`run-worker.sh` 在子进程中设置
  `LD_LIBRARY_PATH`、`HF_HOME` 和 `ANOTA_SPEECHRANK_BUNDLE`，不修改全局 CUDA、PATH 或 shell 配置。
- ASR 引擎是 faster-whisper / CTranslate2。该部署环境未额外
  安装 PyTorch；既有 PyTorch GPU 算子检查见上一份环境报告。

`run-worker.sh`、`smoke/`、依赖锁、模型缓存与服务数据库属于这次独立交付目录，
不随 Git clone 提供。下文维护命令面向已有部署；新机器应先按
[语音流程](speech-smoke.md)和[运行环境矩阵](runtime-matrix.md)建立环境、准备输入与模型。

## 真实测试结果

使用 FLEURS **train split 固定前缀**真人录音，英语、普通话各 10 条，总时长约 200.36 秒。
全部音频在远端逐条核对原始 SHA-256。模型为 `Systran/faster-whisper-base`，
固定 revision `ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66`。
faster-whisper 1.2.1、CTranslate2 4.8.3、PyAV 16.1.0；beam size 5，CPU 线程 4。

| 项目 | CPU int8 | CUDA float16 |
| --- | --- | --- |
| 新推理 | 20/20 成功，0 缓存、0 失败 | 20/20 成功，0 缓存、0 失败 |
| 推理流水线内部耗时（`elapsed_ms`） | 5.700 秒 | 7.019 秒 |
| 外层进程 wall time | 5.786 秒 | 7.149 秒 |
| 缓存续跑 | 20 命中，0 新推理 | 20 命中，0 新推理 |
| DSP / VAD / 覆盖质检 | 20 complete，0 partial，0 failed | 20 complete，0 partial，0 failed |
| 英语 WER | 20/186 = 10.75% | 20/186 = 10.75% |
| 普通话 CER | 109/365 = 29.86% | 126/365 = 34.52% |

这些样本不是独立保留的质量测试集，结果不构成冻结质量基准或泛化结论。
WER/CER 按 `sum(S+D+I) / sum(reference units)` 聚合；文本归一化规则及逐条结果保存在
CPU/CUDA 各自的 `evaluation.json`。

这是小规模工程验收，耗时包含首条加载及初始化，未控制已有 ComfyUI / 桌面负载，
不据此宣称 GPU 加速或模型质量提升。不同精度转录有差异；中文指标仍有明显改进空间。
两条路径的质检均在 CPU 上运行，“CUDA”指 ASR 推理设备。

该历史快照的远端局部回归 **54 passed**，限定 speechprep、语音后端、API 与
SpeechRank runtime 四个测试文件，并非当前全仓测试结果。
审核模型五文件 bundle 完成字节哈希验证并单独打包；相关 runtime 回归使用替身模型，
不证明这次远端真实 SpeechRank 模型加载或预测通过。

FLEURS 英语即使满足 CPU/int8 等精确 ASR 来源约束，也只属于 SpeechRank 探索使用，
有效性未经验证；中文与 CUDA/float16 不属于支持的 ML 域。
若所选队列中任一可参与排序、显示 ASR 建议的语音任务不满足 ML 约束，
**整个所选队列中这类任务统一回退 QC**，
不会混用 ML 与 QC 分数。两套中英混合批次均有中文任务。
完整支持域与其他独立集成记录见 [ML 队列指南](audio-ml-review-queue.md#supported-asr-domain)。

保存的 Windows 客户端 HTTP 验证记录支持：首页 HTTP 200、两个 20 条队列、

## 使用与维护

以下为 Linux 部署机上的 Bash 命令。SSH 登录后，将 `DEPLOY_ROOT` 设为实际交付根目录：

```bash
DEPLOY_ROOT="$HOME/projects/anota-5080-20261018"
cd "$DEPLOY_ROOT"
systemctl --user status anota-5080.service
journalctl --user -u anota-5080.service -n 50
```

需要重启时运行：

```bash
systemctl --user restart anota-5080.service
```

需要暂停此工作台时运行：

```bash
systemctl --user stop anota-5080.service
```

复用交付目录中的入口运行新任务，使用新的输出与状态路径；同一任务续跑保留原路径。
必须从交付根目录开始：wrapper 会切换到其中的 `app/`，下方 `$PWD` 在调用前展开为绝对路径。

```bash
cd "$DEPLOY_ROOT"
mkdir -p runs/my-cpu-job
./run-worker.sh -m speechprep transcribe \
  --manifest "$PWD/smoke/manifest.jsonl" \
  --output "$PWD/runs/my-cpu-job/asr.jsonl" \
  --state "$PWD/runs/my-cpu-job/state.db" \
  --model base --revision ebe41f70d5b6dfa9166e2c581c45c9c0cfc57b66 \
  --device cpu --compute-type int8 --cpu-threads 4
```

GPU 任务改为 `--device cuda --compute-type float16`，并使用独立任务目录。
`run-worker.sh` 保留调度器设置的 `CUDA_VISIBLE_DEVICES`，不将 GPU 编号写死。
CPU-only 机器需要按 CPU requirements 建立自己的环境；此 5080 环境的 GPU 库不应成为
CPU Web 服务的强制部署依赖。

## 集群扩展边界

当前保留相同 Python CLI / manifest / provenance 协议。未来调度适配层可将不同
manifest 分片交给 CPU 或 GPU 作业；每个作业拥有独立 state DB、锁和输出，合并时
校验输入覆盖、重复 item ID、失败和权重/配置身份。计算节点需可访问数据路径与预下载模型。
不让多个节点写同一个 SQLite，也不将人工审核 Web 服务复制成多个 SQLite 写入者。

尚未实现或验收 Slurm 提交器、分片合并器、跨节点恢复或 DDP/FSDP。
独立语音样本优先按任务分片；是否需要分布式训练取决于后续具体 TTS 模型。
本次部署没有包含其他 TTS 合成或训练仓库。
