## 数据清单与隔离

首选 [Google FLEURS 数据卡](https://huggingface.co/datasets/google/fleurs/blob/main/README.md) 的 `en_us` 和 `cmn_hans_cn`。它提供真人朗读音频及转录，适合验证 ASR 与数据工程。它不是医疗电话语料，结果只代表所选数据条件。[FLEURS 论文介绍](https://research.google/pubs/fleurs-few-shot-learning-evaluation-of-universal-representations-of-speech/)

| 数据部分 | 数量 | 用途 |
| --- | --- | --- |
| 冒烟集 | 每语言从官方 train 固定抽 10 条，共 20 条 | 调通下载、音频解码、ASR、Anota 和导出 |
| 开发集 | 每语言从官方 validation 固定抽 30 条，共 60 条 | 定义评分规范、排查参考匹配、选择配置；LLM 提示词只在这里调整 |
| 冻结测试集 | 每语言从官方 test 固定抽 100 条，共 200 条 | 配置冻结后比较模型；输出完整结果，不只挑成功案例 |
| 条件退化测试 | 从每语言测试集预先选 20 条，各产生电话带宽和加噪两个版本，共 80 个派生片段 | 检查退化条件下质量与耗时；它们属于原始 40 条的重复条件，不计成 80 个独立样本 |
| 工程异常样本 | 约 10–15 个程序构造文件 | 损坏文件、空文件、纯静音、极短音频、同名不同内容、哈希变动等；单独统计 |

先只获取所需语言/分片，记录实际下载量；不下载完整多语语料。固定抽样种子、数据仓库 revision、官方 split、源音频标识、原始句子/来源组和音频 SHA-256，写成可复用清单。数据卡的许可标记为 CC BY，实际使用时归档该 revision 的许可和引用信息；仓库提交清单与脚本，音频和模型权重放在本地忽略目录。

保留官方 split；数据卡说明 train 与 dev/test 说话人不同。发布字段不提供可直接使用的逐人 speaker ID 时填 unknown，不用音频文件 ID 假装 speaker ID。所有同源派生音频留在同一 split。跨语言平行句子的关联必须先核实，不按数组下标直接对齐，更不假设已排除模型预训练接触。

电话条件使用固定的 8 kHz 带限/编码再转换至 ASR 输入格式，并记录参数；加噪条件使用固定种子、已知噪声来源及明确 SNR 算法。报告称为“模拟退化”，不称为真实电话录音。原始音频始终保留，重采样不被描述成恢复原始信息。

本周的人工听音只用于中英文转录修正和个案分析。已有 EN→ES 合成集继续充当旧功能回归，不把不会西语的人工确认当作独立英西黄金标注。业务用数字、否定、日期等对照例可以补约 20 条合成规则测试，但单独报告，不用于估计自然通话中的错误发生率。

## 数据契约与 Anota 改动

原始数据、模型假设、机器建议、人工修正和评测答案应拥有不同的存储字段与可见性。ASR 转录不是已确认 source truth；LLM 修改也不是 reference。

建议新增或扩展的文件如下，均为后续实现任务：

| 文件位置 | 职责 |
| --- | --- |
| `speechprep/cli.py`、`speechprep/manifest.py` | 离线任务入口、规范化 manifest、运行配置与内容身份 |
| `speechprep/asr.py`、`speechprep/state.py` | 一次加载模型、按文件推理、成功结果缓存、失败/恢复状态 |
| `speechprep/anota_export.py`、`speechprep/evaluate.py` | 从 manifest 生成审核任务；独立使用 reference 评分 |
| `speechprep/vendor/` | 精选现有 utils；保留原文件哈希、来源说明和相关许可 |
| `requirements-speech.txt` | ASR/音频可选依赖，与 Web 服务的基础依赖分开 |
| `app/models.py`、`app/db.py`、`app/importer.py` | `speech_asr` 任务类型、迁移、音频注册表、转录修订 payload |
| `app/main.py`、`app/tasks.py` | 安全音频访问、提交分派、字段白名单、同源任务标识 |
| `static/app.js`、`static/style.css` | 音频播放、时间定位、原始转录与修正 diff、有效操作计时 |
| `app/export.py`、`app/quality.py` | 导出音频来源/修订/建议使用记录，按任务类型统计 |
| `app/speech_suggestions.py` | 复用已有模型连接与失败处理，独立定义语音辅助建议契约 |

最小 manifest 字段：

```text
schema_version, item_id, parent_id, corpus, corpus_revision, split
audio_id, audio_sha256, duration_s, sample_rate, channel_count
language, language_source, speaker_id, speaker_verified
asr_text_raw, asr_segments, word_timestamp_status
asr_model, model_revision, compute_type, decoding_config_hash
run_id, status, error_code, elapsed_s, cache_hit
reference_id, license_id
```

`reference_id` 指向独立评测存储。审核 API 不返回该答案。原始本地路径仅存在于服务端音频注册表，不由浏览器提供任意文件路径。保存 `language_source` 是为了区分数据集已知语言、模型识别和人工确认。

转录修订建议单独存入 `speech_annotations`，关联 `assignment_id/task_id`，至少包含 `annotator`、`corrected_transcript`、`uncertain_spans`、`reason_codes`、`active_ms`、`wall_ms`、`suggestion_exposure`、`created_at`。所有更正追加新行，撤销与最新有效版本沿用既有工作流。翻译 QA 的 AnnotationPayload 保持原语义。

播放器首版支持播放/暂停、0.75×/1×/1.25×、指定片段回放。为播放器定义独立快捷键，避免现有空格提交与播放冲突；编辑框与快捷键的焦点行为有明确测试。波形编辑器和词级拖拽不进入首版。

## 优先做的工程优化

1. **模型加载和任务执行分离。** 复用已有 ASR 模型缓存思路，每个 worker 加载一次模型。默认 ASR worker=1，Qwen worker=1；两个重负载阶段分开测。首先用 `faster-whisper base/small + CPU int8`，模型尺寸是实验变量，不预设 small 更划算。[faster-whisper 官方 CPU 与 GPU 说明](https://github.com/SYSTRAN/faster-whisper)
2. **成功结果可恢复。** 缓存身份包括音频哈希、模型 revision/权重标识、解码参数、前处理版本；LLM 建议还包括提示词和词表版本。输入内容改变即失效。失败不能写成成功缓存，也不能回退为模拟转录。
3. **逐条写入，避免整批重跑。** 本地状态库与唯一 ID 负责记录 pending/running/succeeded/failed；产物先写唯一临时文件再原子替换。重启后校验哈希再复用，不仅依赖文件存在。多写者保护必须有真实互斥，不能通过忽略锁错误实现兼容。
4. **推理移出 Web 请求。** ASR 与建议预计算；页面只读取已有产物。模型不可用时仍可领取、听音、提交和导出。UI 显示 pending/unavailable，不用模型默认分数替代缺失结果。
5. **过滤改为可审核路由。** 单独记录损坏、静音、低置信、噪声、短句、未知语言等原因；有效困难样本保留在待审核池。训练集收录规则与审核池规则分开。参考答案只用于评分，不能参与选择一个“更漂亮”的测试集。
6. **先优化实测瓶颈。** 分开计时下载/解码/重采样/模型加载/推理/写盘/审核。模型加载原本已缓存的路径不能冒充新增优化；比较必须使用同一输入和配置。

## 验收指标与判定

| 类别 | 本周验收口径 |
| --- | --- |
| 流程完整性 | 冻结输入 100% 有终态与来源记录；有效样本推理成功率目标 ≥99%；未成功的样本继续保留在主报告，不静默排除 |
| 恢复正确性 | 在半批完成时中断，恢复后不缺项、不重复任务；缓存成功项的推理次数为 0；更改音频/模型配置能触发正确失效 |
| 内容完整性 | 音频、模型假设、人工修正能逐项关联；同一数据快照重复导出哈希一致；故意篡改一个产物会失败或明确失效 |
| 服务可用性 | LLM 服务关闭时完成全部人工流程；本地单用户、固定空闲条件下 claim/submit P95 目标 <500 ms，推理运行时另报一组，不混合计时 |
| ASR 质量 | 英文 WER、中文 CER，均报告 corpus 聚合编辑距离/参考长度；同时给原始与固定规范化口径、逐条结果、失败数、正常/退化条件分组 |
| 数字与关键项 | 在人工确认的小规模专项集中报告数字、日期、单位、否定的遗漏/替换及分子分母；未知项不默认正确；不以单一总体 WER 代替 |
| 性能 | 冷启动时间、未命中缓存的总 RTF、逐文件 P50/P95、峰值 RAM、总处理时长；模型加载与预处理开销另列；缓存命中速度不作为 ASR 加速倍率 |
| LLM 建议 | 建议覆盖率、放弃判断率、模型无效输出率、建议延迟、新增错误、原本正确却被建议改错的比例；逐项保存原始输出与 diff |
| 可复现交付 | 配置、数据清单、依赖版本、模型来源、评分规范、原始结果和图表生成命令齐全；相同输入可以复算所有表格 |

WER/CER 中推理失败的有效音频按空假设参与主质量统计，并单列系统失败；不只计算成功子集。纯静音等参考为空的异常样本使用“是否产生非空转录/产生多少内容”等指标，不用除零的 WER/CER。

英文评分先固定 Unicode、大小写、标点与空格规则；中文评分固定 Unicode 与标点/空格规则。保留数字、单位和否定的语义差别，避免规范化把重要错误消除。原始文本不可覆盖。报告中每语言分别列出，不能把中文 CER 与英文 WER 简单平均。

RTF = 指定阶段墙钟处理秒数 / 输入音频秒数。报告模型加载摊销与否、并发数、线程数和缓存状态。本周先建立可复现基线，不承诺未实测的 RTF≤1 或 AMD 加速倍数。

质量提升与工程交付分开验收：项目可以成功证明某模型更慢且无质量收益。只有冻结测试集上的配对结果支持时才声称改善；用 parent_id 分组计算区间，所有退化版本随父样本一起重采样。开发集上的模型选择不反复用测试集修正。

## LLM 能帮助标注员到什么程度

本周定位为“带来源的检查建议”。当前 Qwen 接口处理文本，不会听音频。它可以比较两份 ASR 候选、检索已确认术语、指出数字/否定冲突、整理待回听问题；不能通过文字推断原音频到底说了什么。

| 能力 | 本周实现方式 | 人工仍负责什么 |
| --- | --- | --- |
| 术语与格式检查 | 词表及规范检索，附词表条目 ID | 词表是否适合当前语境、音频是否真的包含该词 |
| 定位疑点 | 标出两个 ASR 候选不同的文本区间及对应时间范围 | 回听并选择正确内容；时间戳不可用时显示不确定 |
| 转录修正建议 | 显示备选与理由，默认不覆盖、不自动提交 | 逐项采纳、修改或拒绝；重要数字与否定必须回听 |
| 审核排序 | 综合规则冲突、模型分歧和音质信号，另保留随机抽样 | 判断困难案例与确认是否应保留 |
| 标注整理 | 将人工选择转换为结构化记录，校验缺失字段 | 确认最终转录与不确定区间 |

两种 ASR 模型若属于同一家族，它们的共同错误可能相关；一致不是正确性证明。LLM 自报 confidence 只用于记录，未经校准不触发自动通过。

本周建议使用冻结的 40 条测试样本（每语言 20 条，事前抽样）做离线小实验：保留 raw ASR、建议和最终采纳文本，使用独立保存的公共转录评分；模型请求中不包含参考答案。检查建议是否减少错误，特别记录从正确变错误的修改。人审后结果与原始机器结果分别报告。由于同一个人审核、样本少且存在学习效应，不据此宣称“节约了多少标注员时间”。

界面增加有效操作计时：前台操作与回听计入 active_ms，离开页面及显式暂停单列；wall_ms 保留。机器预计算耗时、等待时间、复核与返工都单列，供将来多人对照使用。本周只验证埋点和统计正确。

研究也支持这种谨慎的实验设计：一项 350 名参与者的主观任务实验发现，展示 LLM 建议会改变人工标签分布，且没有带来标注提速；这一结论不能直接替代中英 ASR 实验，但足以说明不能把“人工点过确认”当成独立真值。[Schroeder 等，ACL 2025](https://aclanthology.org/2025.findings-acl.1323/)

更接近领域标注的 AnnoHID 研究在印尼语医疗文本上观察到部分一致性与 NER 质量改善，同时没有减少标注时间，并提示概念规范化偏差；因此时间、错误和一致性必须分别测。[AnnoHID，ACL 2026](https://aclanthology.org/2026.acl-demo.67/)

未来若安排正式人工实验，比较“同样的 ASR 草稿与工具”“增加证据提示”“增加预填标签”三种条件；同一人不重复看到同一源样本，各条件平衡样本难度与顺序，由独立审核确定参考。主要衡量最终残留错误和总人工成本，κ 只作为补充。

## 低资源与极少资源语言的扩展

本周能交付的是语言扩展接口与未知状态处理。没有该语言审核者时，只能报告公开转录上的机械指标、运行覆盖和失败，不能把 LLM 的解释当成语义正确性验证。多语 judge 的研究发现表现与一致性随语言变化，低资源语言尤其需要单独校准。[Fu 与 Liu，EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.587/)

首先区分资源缺在哪里：音频不足、可靠转录不足、双语平行文本不足、领域术语不足、还是合格审核者不足。每种短缺需要不同的方案。

| 情况 | 可落地的 LLM/工程用途 | 不应跳过的验证 |
| --- | --- | --- |
| 已有多语 ASR，但人工转录少 | 比较候选、挑出分歧、去重与多样性采样，把有限审核时间用于有价值样本 | 用少量当地语言审核建立留出集，比较随机采样与定向采样 |
| 有当地语言审核者，领域平行句少 | 从审核过的术语表检索、提供对照候选、整理口述解释、构造待确认的句子变化 | 每个新增术语/译句经人工确认；合成数据与真人数据分开 |
| 文字资源极少或正字法未统一 | 保存多种转写、音频时间戳、词汇解释和来源；帮助组织词典与数据 | 与语言使用者确定转写规则；不能统一改成英语习惯或删除有意义的音调符号 |
| 模型没有该语言能力且无审核者 | 做音频管理、切分候选、重复检测和覆盖分析 | 内容正确性保持 unknown；先解决语言专家/社区参与，而不是让 LLM 自我验证 |

扩展契约提前支持 `language`、`dialect`、`script`、`orthography_version`、`reference_status`、`normalizer_version` 与 `unsupported/abstain`。规则按语言注册；没有词法规则时返回 ABSTAIN，不能套用英文否定词表或固定长度比。保存原始 Unicode，展示与评分规范化分开，特别保留音调、附标和脚本差别。

后续可从 FLEURS 中选一个已有模型支持、且能获得审核帮助的语言进行工程试验，再研究实际极少资源语言。把标注预算限制为 30/60/120 分钟可测试“少标注”策略，但不能声称基础模型从未见过该语言，也不能把此设置等同于真正零资源。

下一轮最有价值的比较是：同样专家时间预算下，随机抽样与“分歧 + 多样性 + 固定随机保留”谁能产生更多合格数据、降低更多留出集错误。模型一致、回译相似、另一个 LLM 赞同都只是筛选信号。TTS 合成语音可以作压力测试或增广，不作为唯一测试集。

## 首个工作包与本周最终产物

第一个工作包只包含四件事，完成后再扩展模型和界面：

1. 固定中英 20 条真实音频、来源信息、参考存储与数据契约。
2. 复用独立 utils，运行一个 CPU int8 ASR，保存真实输出、用时与模型身份。
3. 将 20 条结果导入持久 Anota 数据库，完成音频播放、修正和带来源的导出。
4. 在相同输入上验证重跑、断点恢复、参考不进入模型输入、人工修正不覆盖原始假设。

最终交付清单：

- 一个离线批处理入口及版本化 manifest。
- 一个可听音、修正、回溯的 Anota 演示流程。
- 一份中英文固定样本数据卡和来源清单。
- 一份 ASR 质量、性能、失败与恢复报告。
- 一份 LLM 建议离线实验记录；若 D5 时间不足，交付契约与实验脚本，标记为未运行。
- 一组与新增行为直接相关的测试：迁移、音频路由、字段隔离、失败恢复、导入版本和导出哈希。

本周的展示重点是：同一条音频可以从来源追到 ASR、建议、人工修正和最终数据；识别错误和系统失败均能被发现与复现。低资源语言能力通过同一接口扩展，并按语言分别验证。
