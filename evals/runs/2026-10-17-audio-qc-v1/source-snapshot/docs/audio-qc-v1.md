# 音频质检 v1：设计、冻结实验与审核记录

状态：实现和工程验证进行中。本文的实验协议在首轮实验前写入；每次运行另存协议、配置、源文件哈希及逐条报告。实际结果见文末运行记录，未完成的人工实验必须保持 `pending`。

## 目标与边界

输入原始音频及可选的 ASR 文字、词和片段时间戳，生成可定位的声学异常、语音活动区间、转录时间覆盖疑点，并在 Anota 中通过波形跳转、选区和循环回听完成复核。原始录音、ASR 候选和人工修订分别保存；质检提示不能自动成为人工标签。

本版检测的是信号与时间覆盖异常。它不能判断同音词、数字、否定或专名是否正确，也不能把没有提示解释为转录正确。VAD 区间是模型判断，ASR 时间戳也可能有误；两者冲突是回听线索。静音、低音量、接近满幅均不等于某种语义错误。特别地，满幅附近样本只支持“疑似削波”，不证明录音链路发生削波。

## 独立分析模块

`speechqc` 不依赖 FastAPI、数据库或 Anota 页面，公共入口是 `analyze(audio_path, transcript, config)`、独立缓存入口及批处理 CLI。转录输入只取 `asr_text`、`segments`、`words`；不读取 `references.jsonl`、人工最终文本或评测答案。音频字节哈希、规范化转录哈希、分析器版本及参数共同标识一次分析，修改任一输入应使缓存失效。

报告 `speechqc-v1` 包含：

| 字段 | 用途 |
| --- | --- |
| `analysis_id`、音频/转录哈希、版本、`config`、`detectors` | 溯源、缓存和复验 |
| `status`、`warnings` | 区分完整结果和依赖不可用等部分结果 |
| `waveform` | 有界大小的分桶最小/最大振幅，供页面绘制 |
| `metrics` | 峰值、RMS、近满幅比例、低能量比例和直流偏移 |
| `vad` | 实际 VAD 状态、语音区间与失败原因 |
| `coverage` | 词/片段时间轴依据、语音被文字覆盖/未覆盖秒数、文字在语音外的秒数 |
| `issues` | 稳定标识、类型、时间范围、优先级、解释及证据 |

处理各声道时避免正负相位抵消掩盖异常；VAD 使用各声道的实际判断合并语音区间。覆盖检查优先使用有效词时间戳，否则使用片段；没有时间戳的全文不能假装覆盖整段音频。VAD 不可用时保留 DSP 与波形，明确标记覆盖检查不可用，不能将其当成无语音。

检测参数在运行前冻结，属于可调整的工程阈值，不能称为已校准的错误概率。默认阈值及模型参数以每次运行的 `config.json` 和逐条报告为准；更改配置后需要新的运行目录，不能覆盖既有记录。

## 本地操作与审核

在 Anota 根目录安装离线分析的可选依赖，生成新的富化 manifest，再导入独立数据库：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-audioqc.txt
.venv\Scripts\python.exe -m speechqc analyze --manifest runtime/speech-smoke/asr.jsonl --output runtime/audio-qc-v1/enriched.jsonl --cache-dir runtime/audio-qc-v1/cache
.venv\Scripts\python.exe run.py --speech-manifest runtime/audio-qc-v1/enriched.jsonl --db runtime/audio-qc-v1/review.db --batch audio-qc-v1 --suggestions --port 8422
```

`--suggestions` 用于显示机器疑点。盲审批次应隐藏机器提示；基础波形和手动选区可用于回听。每个疑点可以跳转到带上下文的区间；选区循环帮助比较声音和文字。人工确认后才修改转录或保存听不清的区间。仅点击疑点或播放，不代表接受机器结论。

CLI 把分析报告附加到 `audio_analysis`，保留 ASR 字段，失败写入 `audio_analysis_error`；部分/失败运行返回非零退出码。生成新的输出文件，不覆盖原 ASR manifest；重跑相同输入可复用独立缓存。应用导入应校验音频身份、转录哈希、报告 schema、区间边界和分析器版本。若输入变化，要重新分析，不能把旧报告附到新文字上。

分析不调用 ASR 或 LLM，也不下载额外 ASR 模型。VAD 使用 faster-whisper 包内的 Silero ONNX 资源，报告保存实际模型哈希和运行库版本。首次安装依赖仍需要包源网络访问。离线运行缺少依赖或模型时，以部分报告和明确提示结束相应检查。

## 本轮预注册的工程实验

本轮只回答三个问题：已知构造的声学异常能否被相应规则提示；真实音频分析和人工构造的时间覆盖冲突能否贯通；独立缓存的复跑行为与耗时是否符合预期。不评价人类节省时间、总体转录准确率、真实错误召回率或临床风险识别能力。

冻结顺序：先写本文和评测脚本，再保存 `protocol.json`、`config.json`、源代码快照及输入哈希，然后运行分析。首轮结果之后不按这 20 条样本调阈值；后续调参另设开发集、运行 ID 和变更理由，保留本轮失败及限制。

### A. 已知构造的 DSP 验证

固定 16 kHz、3 秒，确定性构造下列波形；这些信号不是自然语音。音频只保存在临时目录，报告保留生成参数及音频哈希。

| 条件 | 已知事实 / 预先指定检查 |
| --- | --- |
| 正常正弦基线 | 440 Hz、峰值 0.2；不应出现 `low_level`、`near_clipping`、`dc_offset` |
| 全静音 | 全零；应出现 `low_level` 或 `low_energy` |
| 低音量正弦 | 440 Hz、峰值 0.0001；应出现 `low_level` |
| 满幅附近方波 | 幅度 ±0.9999；应出现 `near_clipping` |
| 直流偏移正弦 | 基线正弦加 0.15；应出现 `dc_offset` |
| 反相双声道 | 两声道分别为基线正弦和其相反数；RMS 应明显高于 -35 dBFS，不能因平均抵消而出现 `low_level` |

这里的“通过”只指预先指定的数值/规则断言。其他提示照实计数，不当作真实误报率。对于人工注入 VAD 区间的单元测试，记录为区间运算测试，不计入实际 VAD 模型效果。

### B. 真实音频观察与成对受控变体

完整输入为现有 `runtime/speech-smoke/asr.jsonl` 的全部 20 行，对应 Google FLEURS 英语/普通话各 10 条固定训练分割录音。来源、版本、许可及取样限制见 [数据卡](speech-smoke-data-card.md)。源音频和 ASR 文件只读，不修改原数据库，不用官方参考文本驱动检测。

每条父录音产生三个条件：

1. `original`：原始音频和现有 ASR 时间戳。仅观察各检测器提示数、状态、时长和耗时，不给未审核提示贴“正确/错误”标签。
2. `transcript_removed`：保留原音频，删除全文、词和片段。这是完全缺失转录的受控异常。只有原始报告存在实际 VAD 语音且最长语音段达到预定最短提示时长时，才进入该项可检出分母；其余仍保留在总分母，并单列原因。
3. `audio_silenced`：保留 ASR 文字及时间戳，将音频替换为同采样率、声道和样本数的全零音频。只有原报告的有效文字时间轴至少有一个区间达到预定最短提示时长时，才进入该项可检出分母。期待 `transcript_without_speech`；这是构造的覆盖冲突，不代表自然 ASR 幻觉检出率。

以上是 20 条父录音的相关变体，不能宣称获得 60 个独立样本，也不能把其结果当作真实录音错误的准确率。说话人未知、可能同句多录、训练分割和潜在预训练污染等限制继续适用。原始分析失败、VAD 不可用、条件不可检出均必须保留完整分母和状态，不能仅报告成功条目。

### C. 缓存和性能

每个条件使用独立的初始空缓存，先分析一次，再用同一参数复跑一次。分开报告空缓存和缓存复跑的调用数、成功数、失败数、总耗时、中位数和 P95；缓存重复调用应得到相同语义报告。空缓存耗时包括音频读取/解码、哈希、VAD、DSP 和序列化，首条还可能包含进程内模型初始化。缓存复跑仍可能读取并哈希输入。两者均不能称为纯模型推理耗时。报告总音频时长与累计调用耗时；小规模单机运行只用于工程观察。

### 保存与复验

评测脚本 `scripts/evaluate_audio_qc.py` 创建不可覆盖的运行目录，保存：

- `protocol.json`、`config.json`、`source-snapshot/`：首轮前冻结的规则、参数、代码和文档。
- `observations.jsonl`：完整逐条原始报告、条件、父录音、预期断言、可检出性和两次调用耗时。
- `summary.json`：完整分母、检测器提示计数、构造断言结果、性能、限制及输入未改变的校验。
- `human-audit-template.csv`：全为 `pending` 的复核表，不伪造人工听音结果。
- `artifact-hashes.json`：所有已保存运行文件的 SHA-256；清单自身不递归哈希。

持久化记录不包含音频副本和机器绝对路径；源数据由固定数据卡和哈希定位。每次运行检查原 manifest 与父音频前后哈希一致。失败记录保留错误类型及脱敏说明。

在 Anota 根目录运行：

```powershell
.venv\Scripts\python.exe scripts/evaluate_audio_qc.py --manifest runtime/speech-smoke/asr.jsonl --output-dir evals/runs/2026-10-17-audio-qc-v1
```

同一目录不能重跑覆盖。复验请使用新的目录，并比较配置、源哈希及逐条结果；耗时允许因设备负载变化。

## 后续人工对照实验（尚未执行）

先在独立数据上由至少两位有能力的审核者听音建立错误与区间标注，分歧经第三方裁定；数据集参考文本不能自动标成人工 gold。开发集用于选择阈值，冻结测试集用于最终对比，按说话人/录音来源分组防止泄漏。

比较 A：现有播放器；B：波形和循环回听；C：B 加质检提示。控制其他界面和任务说明一致。将相同录音分配给不同审核者；同一人不能在不同条件反复审核同一录音，以免记忆形成假收益。随机分配并平衡语种、音质、说话人和时长；若同一审核者跨条件参与，使用不重复录音和顺序平衡。

预先指定主指标：固定审核时间预算内找到的真实错误数，以及完成审核后残留错误率。辅助指标：每音频分钟审核用时、数字/单位/否定错误召回、提示命中率、每音频分钟误报数、无提示区域的随机抽检漏报率和可用性反馈。记录回听/暂停/修改等操作，但不要将页面停留时间等同有效劳动时间。

计时排除休息和技术中断并保留排除理由；未完成任务仍在分母中。采用按父录音和审核者分组的统计分析及置信区间。根据先导实验估计方差后再设计样本量，不能用本轮 20 条对效率改善作显著性结论。审核者可以隐藏提示；评分 gold 的审核者应对条件和机器提示盲法。

## 扩展接口与拆仓条件

未来的第二路 ASR、音频模型、LLM 和学习排序器均作为独立 evidence provider，添加自己的版本、配置、运行状态、证据和区间，不篡改 DSP/VAD 原始结果。LLM 只解释已给证据、提出复核问题或明确放弃；模型输出不直接成为人工修订。多模型一致不代表正确，分歧用于排序；未来概率需独立校准，当前优先级只是规则。

缓存应覆盖每个 provider 的输入、版本和参数，某一 provider 不可用不能伪造空结果。引入新 provider 时在冻结集上分别比较基础 DSP、+VAD、+覆盖、+多 ASR、+LLM 的增益、误报、延迟和成本，保留退化与失败。

在 Anota 与独立批处理都使用同一 API、数据 schema 和缓存契约，且模块测试不依赖应用数据库后，可以将 `speechqc`、测试、协议和 CLI 一起拆为独立 repo。页面和人工审核数据库继续属于 Anota。拆仓前补齐包许可证、模型许可证说明、兼容性版本策略和迁移测试。
