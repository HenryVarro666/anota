# LibriSpeech 音频 QC 复核排序实验：冻结协议 v1

协议日期：2026-10-17。协议 ID：`audio-qc-ranking-v1`。

本文在本轮读取 gold、计算 WER 或查看排序效果之前确定。运行器须把本文、配置与实际使用的源码复制到每次运行的冻结目录，并记录 SHA-256；文件存在本身不证明已经完成冻结，运行记录中的阶段顺序和哈希才是证据。本文不包含实验结果。总体动机见 [已有标签驱动的自动实验计划](audio-qc-golden-benchmark.md)。

## 1. 问题与范围

利用现有 LibriSpeech 官方参考转录和已经产生的 ASR 结果，比较冻结的 QC 排序、随机排序和时长排序：如果只选取全部音频时长的 10% 或 20% 进行整条录音复核，所选录音包含全部转录错误的多少比例？

本轮只进行离线评估，不重新执行 ASR，不训练排序模型，不调整 DSP、VAD、覆盖检查或排序阈值，不改变现有 ASR 任务。QC 阶段可运行音频分析，但不接触参考文本。参考转录只用于最后的独立评分。已有模型时间戳不是人工词时间 gold，不能据此计算疑点区间的词错误定位准确率。

用户已同意先对已完成结果的固定快照给出中期结果，再使用同一套冻结规则衔接全量。中期结果不能用于调参或改变全量主分析。无论结果有利或不利，均保留。

## 2. 数据集与两种评估队列

目标全量队列为本地已准备的 LibriSpeech `test-clean` 与 `test-other`，共 5,559 条录音。以冻结的准备清单及其音频身份哈希为目标总体，不以当前成功 ASR 数量重新定义全量分母。

### 2.1 中期队列

中期队列只按快照时已经持久化的终态 ASR 结果选择；选择过程不读取 gold 或逐条错误评分。

- 对每个现有 worker 的 SQLite 数据库使用只读连接，在单个只读事务内取得该 worker 的一致快照；保存 worker 标识、捕获起止时间、快照身份及哈希。
- 多个 worker 的捕获时间可能不同。这是逐 worker 一致快照，不声称是整个运行的同一瞬间原子快照。
- 纳入已有终态结果，包括成功与真正失败。尚未完成、尚未开始或尚未产生终态结果的条目，不作为 ASR 失败，不进入本次中期队列。
- 保存原目标清单数量、纳入数量、排除数量及原因，并按官方 split、说话人和时长描述队列构成。不得按 WER、QC 分数或结果是否方便评分决定纳入。
- 冻结后不随着源任务继续运行而向该中期队列追加条目。再次捕获应建立新的运行记录。

中期队列不是随机样本，可能主要是清单前缀，且受 worker 分配、说话人、章节、处理速度和失败模式影响。中期结果只描述这次快照，不能外推为全量 5,559 条的表现。未完成条目和对应时长单独报告，不能暗示已完成全部评估。

### 2.2 全量队列

全量评估必须同时满足：现有 ASR 运行被其自身状态明确标记为完成；取得的终态结果 item ID 集合与冻结目标清单精确相同，数量为 5,559，无重复、额外或缺失条目。真正失败的终态结果仍进入队列。

若条件尚未满足，继续保留中期报告并等待现有任务；不得把部分结果重命名为全量，不得为本实验另行启动重复 ASR。全量报告引用相同的协议、配置与排序源码哈希；如必须修复影响结果的实现缺陷，须记录偏离、版本及原因，并在同一修复版本下重新运行所有受影响的比较，不能悄悄替换旧记录。

## 3. 阶段隔离与冻结顺序

运行按以下顺序执行并记录时间：

1. 冻结协议、配置、QC 与排序及评分源码、环境版本、种子和输出位置。
2. 捕获 ASR 结果快照，依据清单与终态结果建立队列，保存完整输入快照及哈希。此时不读取参考文本。
3. 对固定队列执行 QC。输入限定为音频、ASR 文本及预测时间戳；参考文本和 WER 不进入分析、排序或失败重试决策。
4. 按本协议生成 QC 分数、所有比较条件的排序和预算选择；保存逐条分数、排序及可复验的选择计划和哈希，并记录 `score_frozen_before_gold` 阶段标记。选择计划至少记录每个组、方法或随机种子的顺序哈希，以及各预算的选中条数、目标和实际微秒数；随机顺序可由已存队列、种子与冻结源码复现，不要求将 1,000 份完整 item ID 排列全部重复存盘。
5. 只有上述产物已冻结后，才调用现有 `scripts/evaluate_speech_smoke.py` 的规范化与编辑距离评分逻辑连接官方参考，计算逐条和聚合结果。
6. 输出中期或全量报告、随机试验明细、失败清单与产物哈希。检查冻结输入和源码未被改写。

gold 不应复制到 Anota 审核任务的可见字段或 QC 输出中。离线评分产物可以保留评分所需的参考与假设，但须与参考不可见的排序产物分开。

活跃 ASR worker 的源数据库和状态文件会正常继续变化，不要求其运行前后哈希相同；只读捕获不得写入这些源文件。完整性复核针对本轮固定快照、准备清单、引用的音频及本轮评分使用的参考文件。记录源身份、捕获时间与快照哈希，不能用不断变化的源数据库哈希冒充可复现输入。

## 4. 固定排序规则

### 4.1 可用性层级

每条录音先获得一个层级，按层级降序排列：

| 层级 | 条件 |
| --- | --- |
| 2 | ASR 终态不是 `succeeded` |
| 1 | ASR 成功，但 QC 不是 `complete`，或转录覆盖检查状态不是 `ok` |
| 0 | ASR 成功、QC 为 `complete` 且覆盖检查为 `ok` |

缺失或无效 QC 报告按 QC 不完整处理并保留原因；不能因为无法得到分数而从队列中删除。ASR 终态声称成功但文本或身份字段不合法属于输入完整性错误，应阻止正式评分，不能无声地当作正常成功。

层级是保守的失败优先复核策略，不是从 gold 拟合的概率。报告须单独列出非零层级的数量、时长和错误贡献，避免把优先挑出 ASR 失败的收益全部归因于声学 QC。

### 4.2 QC 主分数

使用原始 QC 报告中已冻结的 issue 区间与优先级：`high=3`、`medium=2`、`low=1`。令录音时长为 `d` 秒，在每个时刻取覆盖该时刻的所有入选 issue 的最大权重，没有 issue 时取 0：

```text
w(t) = max({priority_weight(issue): start <= t < end} ∪ {0})
score = integral(w(t), t=0..d) / d
```

分数范围为 `[0, 3]`。重叠区间取最大权重，不累加；重复提示不会因重复计数抬高分数。按录音时长归一，分数表示加权提示占据的时间比例，不能解释为错误概率或预计错误词数。合法完整报告没有 issue 时，分数为 0；没有可用报告时，分数为 0，并由层级保留其未知状态。

报告时间戳序列化为六位小数。积分仅允许最多 1 微秒的终点表示误差，并将其截断到清单录音终点；超过此范围或负起点仍报错。这不是放宽声学匹配标准。预算继续使用清单时长换算的整数微秒。

主规则的方法 ID 为 `qc`（“完整 QC”或 `qc_full` 仅为说明别名，不是另一个比较条件）。排序键依次为：层级降序、分数降序、`sha256('audio-qc-ranking-v1:' + item_id)` 的十六进制字符串升序。哈希并列规则独立于 gold，也不沿用按说话人或章节排列的清单顺序。

所有 QC 分析使用冻结的 v1 配置与模型来源。报告分数取未经展示舍入的数值排序，不能按页面显示的小数位制造额外并列。

### 4.3 消融与基线

| 条件 | 分数或排序输入 | 层级 |
| --- | --- | --- |
| `qc` | 全部 QC issue | 使用上述固定层级 |
| `dsp_only` | 仅 `low_level`、`low_energy`、`near_clipping`、`dc_offset`，同样计算最大活跃权重积分 | 使用同一层级 |
| `coverage_only` | 仅 `speech_without_transcript`、`transcript_without_speech`，同样计算最大活跃权重积分 | 使用同一层级 |
| `shortest` | 录音时长升序；相同时使用同一哈希并列规则 | 不使用层级 |
| `longest` | 录音时长降序；相同时使用同一哈希并列规则 | 不使用层级 |
| `random` | 先按 item ID 排序，再使用固定种子均匀打乱整录音 | 不使用层级 |

消融只限制分数使用的 issue，仍共享完整 QC 的可用性层级、底层计算和耗时。因此它们是排序特征消融，不能称为独立运行的 DSP 或 VAD 模型性能、独立推理成本。VAD 本身的 speech/non-speech 比例不额外加入本轮排序公式；转录覆盖 issue 已依赖 VAD。

主分析固定为 `qc`，其余条件均完整展示。不能看结果后将最优消融改称预先指定的主规则。

## 5. 时长预算与选择器

预算点固定为总音频时长的 `5%`、`10%`、`20%`、`30%`、`50%`、`100%`，主问题是 `10%` 与 `20%`。每个排序条件和随机种子在所有预算点复用同一条完整排序。

以冻结清单的正有限录音时长计算整数微秒：

```text
duration_us[i] = round(duration_seconds[i] * 1_000_000)
total_us = sum(duration_us)
budget_us[p] = floor(total_us * p / 100)
```

逐条累加排序后的 `duration_us`，只取不超过 `budget_us` 的最长前缀；首次遇到加入后会超预算的录音时立即停止。不跳过该条去挑选后面的短录音，不截取边界录音，不将局部听取假定为全条错误已覆盖。100% 时应包含队列全部条目。

所有条件使用完全相同的选择器。每个结果须报告目标预算、实际选中时长及比例、欠用时长、选中条数，避免把不同实际用量隐藏在同一个百分比标签下。整录音约束意味着实际用量通常略低于目标预算。

预算单位是音频时长，不是条数、字数或实际人工劳动时间。排序目标没有额外输入 gold 词数或实际错误数；不得用 gold 计算单位时间错误密度来代替 QC 排序。

## 6. 随机对照与分组

随机对照运行 1,000 个种子：`20261017` 至 `20262016`，包含两端。对每个分析组，先按 item ID 排序，再使用记录了 Python 版本的 `random.Random(seed).shuffle` 生成完整顺序；同一个组、同一个种子的全部预算点复用该顺序。

分别执行以下分析，而非只从 pooled 选择结果切出 split：

- `pooled`：当前固定队列全部条目一起排序，以该队列总时长分配预算。
- `test-clean`：该 split 内独立排序，以该 split 总时长分配预算。
- `test-other`：该 split 内独立排序，以该 split 总时长分配预算。

这样可以区分整体挑选更困难 split 的收益与同一 split 内的排序价值。中期快照某个组为空时明确记为空，不产生虚构的 0% 表现。说话人数量与时长构成用于描述队列，不能据此在读过结果后重新选择有利子组。

逐种子保留实际选中时长、条数及全部主指标；汇总均值、中位数、2.5% 与 97.5% 分位数。分位数使用排序后位置 `(n-1)*q` 的线性插值。QC 相对随机的主比较使用同预算下随机均值，同时展示随机分位区间与实际用量。

上述区间反映在固定数据上的随机排序波动，不是数据集抽样或泛化置信区间。本轮不运行数据 bootstrap，不进行显著性筛选，不依据随机种子结果调整种子集合。

## 7. Gold 评分与分母

复用 `scripts/evaluate_speech_smoke.py` 的冻结实现，使用其 NFKC、casefold、标点与英语空白分词规则及确定性的 Levenshtein 编辑计数。必须记录该规范化版本与源码哈希。该 WER 定义未承诺与 LibriSpeech 其他发布结果的文本规范化完全相同，未经核对不能直接跨报告比较数值。

令第 `i` 条录音的替换、删除、插入分别为 `S_i`、`D_i`、`I_i`，`E_i=S_i+D_i+I_i`，参考词数为 `N_i`。对每个组和预算，设选中集合为 `A`，报告：

| 指标 | 定义 |
| --- | --- |
| 错误覆盖率 | `sum(E_i for i in A) / sum(E_i for all i)` |
| 错误录音召回 | `count(i in A where E_i > 0) / count(all i where E_i > 0)` |
| 剩余 WER | `sum(E_i for i not in A) / sum(N_i for i not in A)` |
| 总体 WER | `sum(E_i for all i) / sum(N_i for all i)` |
| 选中录音 WER | `sum(E_i for i in A) / sum(N_i for i in A)` |

所有指标采用累计编辑数与累计参考词数，即微平均；不平均逐录音 WER。错误数可包含插入，因此 WER 不保证小于或等于 1。分母为 0 时输出 `null` 并标明原因，不能置为 0 或 100%；特别是 100% 预算下剩余 WER 不可定义。

真正失败的 ASR 结果沿用评分器规则，以空假设文本参与评分，将参考词计为删除；它们不能从主分母中删除。空的成功转录与失败状态分开计数。中期队列之外尚未完成的条目不计为空假设，不参与该中期分母，但完整报告必须展示其排除数量与时长。

参考缺失、重复 item ID、结果身份与清单不匹配、额外 ID、音频哈希不一致、无效时长等是完整性问题，应阻止正式评分或全量完成判定，而不是静默丢弃条目。QC 运行失败本身属于评估中的可用性结果，应保存失败原因、层级及所属分母。

## 8. 保存产物与复现要求

每次中期或全量运行至少保存：

- 冻结协议、完整配置、实际执行源码快照、Python 与分析依赖版本、模型来源及哈希。
- 目标清单身份、队列清单、ASR 固定快照身份、逐 worker 捕获时间、纳入及排除计数；体积较大的完整输入快照可保存在 `runtime`，报告中记录精确位置和 SHA-256。
- 排序前的原始 QC 报告及失败记录，可使用无损压缩；逐条层级、分数、并列哈希、来源 split、时长和分析 ID。
- 参考读取前已冻结的排序与预算选择计划，以及证明阶段顺序的运行记录与哈希。随机计划保存种子、顺序哈希和各预算选中条数、目标及实际微秒数；完整随机 ID 顺序可根据已存输入和冻结实现重建，无需重复保存。
- 独立评分产物，包括逐条 S/D/I、参考词数、状态和规范化版本；全部条件、组和预算的聚合指标；1,000 次随机试验明细。
- 使用的输入及源码前后完整性检查、运行耗时与缓存情况、失败清单、可读结果报告和产物哈希索引。

不得只保存汇总百分比。若完整输入仅存于本机 `runtime`，须明确复现依赖这些文件，不能声称一个只含文档的仓库克隆已包含全部输入。ASR 历史推理成本、QC 当前计算成本和缓存读取成本分开记录；本轮复用 ASR 不能计作零成本重新推理。

## 9. 验证要求与解释限制

实现验证覆盖：重叠 issue 的最大权重积分、分数范围与消融过滤、层级及哈希并列、固定种子与跨预算同序、整数时长边界、首超即停、100% 全选、空组和零分母、ASR 失败保留、重复或错配身份拒绝，以及先冻结排序再连接 gold 的阶段隔离。

所选录音“包含”错误不等于审核者一定找到并修正这些错误。音频预算 20% 不等于人工成本减少 80%；实际播放、重复回听、定位和纠错开销不在本轮测量范围。DSP 声学提示与转录错误并非一一对应，WER 为 0 的低电平录音不能仅因此称为 DSP 误报。

当前 ASR 与 QC 可能共享 Silero VAD 及其漏检；两者一致不构成独立正确性证据。官方参考是本轮转录任务的 gold，但不提供独立人工 VAD 帧标签，也不保证模型预训练从未见过公开语料。中期的非随机完成样本和全量的公开朗读语料均不能证明新领域表现。

本轮结束后可据结果提出下一版方案，但任何后续学习、阈值选择或看过测试结果后的规则变更都属于新的实验，应使用独立开发数据，并保留本轮全部冻结结果。不能将改进后的测试表现包装成该 v1 协议的预注册结果。
